# Routing Evaluation Bank

Purpose: evaluate Engineering-OS itself. These are **routing tasks**, not invented substitute tests for the target technologies. Once routed, execution must follow the authoritative framework/vendor/standards guidance already cataloged.

For each scenario record:
- selected first-stop document
- additional sources opened
- capability/tool chosen (if any)
- authoritative source used
- prerequisites checked
- irrelevant branches avoided
- evidence requested/produced
- final status and untested gaps

## Scenarios

1. **Web checkout qualification** — determine how to verify a checkout flow, webhook and durable entitlement without treating UI text as sufficient evidence.
2. **Android release readiness** — route from release build through mobile journey, security and current Google Play requirements.
3. **Instagram Reel analysis** — choose an available video-analysis path and require visual evidence not inferable from transcript alone.
4. **Large-repository context cost** — decide whether RTK, Graphify or a memory tool addresses the actual bottleneck.
5. **Web security qualification** — route to standards plus executable SAST/SCA/secrets/config/DAST evidence without claiming absolute security.
6. **Browser UI regression** — distinguish exploratory browser agents from deterministic Playwright regression evidence.
7. **Cross-session coding memory** — compare the existing memory/context options by persistence/privacy/host constraints instead of installing all of them.
8. **External service integration** — find the service wrapper, then verify current official API/auth docs before implementation.
9. **Known production bug** — search troubleshooting/lessons first, reproduce the defect, and require a regression check proving the intended mechanism.
10. **Autonomous coding runtime** — select between host-native agent capability and optional OpenHands/Hermes-style runtimes based on environment and sandbox constraints.

## Scoring without subjective ranking

Report counts, not a single opaque score:
- correct route: yes/no
- canonical source reached: yes/no
- prerequisites verified: yes/no
- evidence boundary preserved: yes/no
- irrelevant major branch loaded: yes/no
- unsupported claim made: yes/no

A scenario is **PASS** only if the first four are yes and the last two are no.
